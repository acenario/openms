## Scope and provenance

This is an offline reconstruction from the supplied `Maplestory_UNPACKED.exe` and WZ files. There is no original recording, original C/C++ source, Windows execution or Nexon server. Authorized Cosmic server-reference code is not original client evidence or Nexon source. Packaged traversal is **not server authorization**. Neither this implementation nor its smoke evidence establishes visual parity with the original running game.

## Recovered graphics and timing

`00712313` reads `Map/MapHelper.img` → `portal` → `game` → `pv` (IDs `0x6b0`, `0x5c1`, `0x6b1`, `0x6af`). The loader installs this looping artwork for types 2, 4 and 7. Its animation call uses mode `0x20`.

`0071259d` selects `ph` (`0x1122`); `00712827` selects `psh` (`0x1123`). `00712d35` uses `ph` for type 10 and `psh` for type 11. The loader places types 10/11 in the manager's `+0xc` collection and stores their `image` variant. Only **empty or absent image** is replaced by string ID `0x3c0`, `default`; an unknown nonempty variant must not fall back silently. The eight supplied type-10 records all use this empty/absent default.

When the selected nearby hidden portal changes, `00712d35` starts the old portal's `portalExit`, clears its current/start layer, and starts the new portal's `portalStart`. Both use mode zero. `0071332c` checks `00443e36()==0` to release a completed Start, install `portalContinue` with mode `0x20`, and release a completed Exit. The runtime mirrors those one-shot/loop transitions for all supplied hidden portals. It does not reverse an in-flight Start animation when departing; it starts Exit.

**Type-11 recovered family:** `0071332c` calls the **ph helper unconditionally** for Continue even though Start/Exit select psh. Extraction now reproduces that exact mixed family; it does not substitute psh Continue. A missing requested ph/psh variant is an explicit original-artwork dependency failure, never a default-variant fallback.

All these graphics call `0043ea3e`; its numeric-frame loop calls `0043f768`. The latter pushes **`0x78` (120 ms)** before converting frame `delay`, string ID `0x15f8`, through `00414d40`. This provides a real original-consumer chain for the portal default; it is **not** inferred from the previous shared extractor's 120-ms policy. Portal extraction explicitly normalizes numeric-string delays, retains explicit nonnegative delays, original origins and alpha endpoints, and rejects negative or nonintegral milliseconds. Equal-time zero frames follow the recovered Gr2D queue semantics documented in [client evidence](client-evidence.md#timed-frame-alpha--verified).

Browser presentation reevaluates this selector each active update; the original invokes the callback when either of its two arguments is nonzero. Precise original callback scheduling/attachment on initial stationary entry remains unverified.

It sets the flag and timestamp when transmitting. `PortalTravelGate`, owned by persistent `InGameSystems`, now retains both pending-token ownership and the interval across successful scene replacement. `0053185c` timestamps the response, including failure; local success/failure/cancellation settlement likewise starts the next 500-ms interval. A stale token cannot release a newer request. `performance.now()` supplies one monotonic application clock; inactive-tab wall time is explicitly browser policy.
- Same-map non-type-4/5 routes take `00957b74`. **Fresh recovery corrects the earlier 120-ms-delay interpretation:** request stores the destination at `+0x2b20/+0x2b24`, request time at `+0x2b28`, and an initial admission deadline `now+120` at `+0x2b2c`. [`0094e5e5`](ghidra-ingame-portals/entities-motion.txt) moves on the next update when `now >= +0x2b28`, then replaces `+0x2b2c` with **now+600**. The browser therefore does not invent a 120-ms travel pause; the shared gate retains the 600-ms same-map recovery after successful commit. Type 4/5 always take the packet-admission path even when target map equals source.
- Original destination entry `00949513` subtracts **10** from selected portal y. The integration must spawn at the exact named destination `(x,y-10)`, not at source coordinates or a random/default spawn.
- After accepted non-type-4/5 ordinary requests, `0094df9b` resolves string ID `0x15ba`, **Portal**, for the Game sound path. Types 4/5 suppress that sound. `00957b74` resolves `0x884`, **Effect/BasicEff.img/Teleport**, for same-map motion. Main receives these exact sound/effect choices with the travel token and dispatches them only after an accepted atomic offline commit. Moving the original request-time effect/sound to accepted completion is deliberate offline failure safety, not original response latency.

The browser latches an **Up keydown edge** independently of held Up, consuming it once before physics. A keydown+keyup within one render interval is therefore not lost. Focus/map replacement clears held and pending edges; subsequent OS repeat cannot rearm until a fresh physical press. This is browser duplicate/bounce safety, not an assertion of identical Windows repeat scheduling. Holding Up or pressing again while loading cannot create a second request. Rejection retains the old scene; generation/destroy guards prohibit stale completion/error mutation. Online Up checks use the predicted local foothold/position. Sending a portal intent does not clear held directions or block walking; only an accepted transition begins the movement/fade boundary. A pending request still prevents duplicate portal intents. Cross-map prepare packets carry the portal sound flag, so the warmed original Portal cue plays at preparation instead of being lost as a destination-field event before its baseline. Same-map portal sound remains an accepted world event.

## Field transition versus same-map teleport

The [transition contract](ghidra-client-corrections/transition-contract.json), [native instructions](ghidra-client-corrections/transition-native.txt) and [original WZ probe](ghidra-client-corrections/transition-wz.json) distinguish two paths; a portal cooldown is not a fade duration.

- **Ordinary field replacement:** `005294ce → 0063988a → 00776e65` reduces native global RGB brightness with `trunc((600−elapsed)*255/600)` for600ms, then sets zero. `00529269 → 00776b64` schedules the ordinary incoming rise to255 over600ms. The outgoing loop is synchronous; incoming fade is scheduled while user construction/gameplay continues. The browser freezes source simulation/input through leaving/loading/covered, prepares the candidate asynchronously, and commits only when both the candidate and black boundary are ready. Input/physics are released at commit/reveal, **not after a second600-ms lock**. Destination movement continues during the600-ms reveal.
- **Same-map non-type-4/5 motion:** relocation occurs on the next eligible update without scene teardown, an asynchronous window-close boundary or global fade. It synchronizes previous/current actor positions at the exact named `(x,y−10)` arrival and preserves field systems, fixed clock, BGM and camera-filter history. Two preloaded original `Effect/BasicEff.img/Teleport` animations restart at the departure and arrival positions: **four80-ms frames,320ms total**, independent of600-ms admission recovery. The provisional120-ms guard is not a travel pause. Types4/5 retain the packet/field path even when map IDs match.
- **Camera:** `00437a31`, with `00437b32/00437b35`, attaches the local-user target at `(x,y−50)`. The recovered Shape2D filter now replaces the earlier immediate-follow implementation; see the filter contract below. `00641ef1` clips the filtered center to `VRLeft+400`, `VRRight−400`, `VRTop+300`, `VRBottom−300` at 800×600, collapsing nonpositive ranges to their midpoint. Other viewport sizes generalize the half-extents as browser policy. A new scene's first filter commit snaps; a same-map relocation retargets the existing filter and therefore visibly eases across the field rather than snapping the camera.
- **Failure/cancellation:** the old complete scene remains owned until accepted commit. Failed replacement restores it and reverses darkness from the current value at the same fade rate; no successful travel sound/effect is emitted. Stale request IDs cannot reveal or cancel a successor. Ordinary developer map selection/reload is an immediate browser path and cancels prior presentation transitions. Revival uses field replacement/fade even when the authored return map has the same ID.

`FieldTransition` owns only bounded presentation state and opaque/visible boundaries; Main owns scenes, abort signals, profile commit and rollback. A full-viewport black overlay above field/HUD approximates native global RGB modulation without changing scene alpha. Async candidate preparation, hidden-tab suspension and completion-time sound/effect dispatch are deliberate browser policies. The [historical native-input report](ingame-validation/interaction-corrections/report.json) exercises its recorded integrated paths; no original Windows parity is claimed.

### Recovered camera-filter dynamics

[`camera.js`](../client/src/rendering/camera.js), the [EXE attachment/filter export](ghidra-client-features/camera/camera-exe-focus.txt), and [original Shape2D DLL decompilation](ghidra-assets/Shape2D.dll/decompiled.c) retain the distinction between the target vector, its filtered public coordinates and clipped viewport. Shape2D `51408d23/51408e33` use filter `0x1e0000`, coefficient 100 and a 28-pixel deadband. For one axis, with distance `D` from the committed history to the integer target and signed elapsed renderer milliseconds `dt`, the remaining distance is `D` inside the deadband, otherwise `max(0, 100000*D/(dt*D+100000))`. The output approaches the target by subtracting that residual with the original direction. Coefficient 100 is **not a 100-ms tween duration**.

Default clipping must use the **physical-space bounds**, not raw foothold extrema. `00641ef1` obtains the rectangle from `00a43e7b`; the [world-bound loader](ghidra-physics-refinements/world-bounds-loader.txt) first applies x+30/−30 and y−300/+10 plus original VRLimit restrictions. Camera expansion then adds left−20, right+20, top−60, bottom+100, with each explicit VR edge overriding its corresponding default. `camera.js` shares `prepareBounds` with physics. Omitting the physical top margin caused upper-platform characters to reach the screen edge even though filtering itself was correct.

Committed history stays double precision; public coordinates truncate to signed integers. Read-only probes do not initialize or commit, and retargeting does not reset history. The [first-pass native gameplay report](native-ui-validation/gameplay/report.json), case `same-map-portal-camera`, traversed actual `hp01→hp01_1`: arrival `(5801,444)` preceded floor settlement `(5801,454)`, global opacity stayed zero, and its 108 consecutive post-relocation X comparisons matched that report's source filter. This is browser/source numerical evidence, not Windows runtime equivalence. That pass did not capture reciprocal travel or each Teleport frame; the older interaction report's four-frame capture belongs to its own earlier build.

The [final native gameplay replay](native-ui-validation/final/gameplay/report.json), source `eb84f90…`, traverses **both `hp01→hp01_1` and `hp01_1→hp01`** through native Up. It records two requests/completions, each600-ms same-map recovery, named arrival/floor settlement, zero global opacity, visible camera travel and actual Teleport pixels. Public observations traverse frames0,1,2,3 then no active effect in both directions. These are wall-clock samples and motion captures, not separate screenshots of each frame or proof of exact80-ms browser scheduling. The final pass does not repeat the first-pass numerical camera comparison or claim Windows parity. It separately confirms authored return-map revival with600-ms leaving/reveal and input released at commit; failure/auto-confirm paths remain historical or unexercised.

Family travel is a distinct local transaction, not ordinary Up-portal activation. The [final Family report](native-ui-validation/final/family/report.json) on its exact `eb84f90…` source exercised native reunion, outgoing summon with visible peer consent, and incoming native receiver travel to a unique portal destination, with held input cleared at modal admission/commit. It also retained a concrete failure: incoming summon to Henesys rejected `Ambiguous destination portal sp`, preserving the source and invitation. Selecting authored portal ID0 must not be confused with proving unique portal-name routing; that report does not claim the duplicate-name destination works.

### Online sentinel portal scripts

An Up request on a sentinel (`tm=999999999`) type 7/8/11 portal whose script is neither a market nor a tutorial program runs that portal's vendored `scripts/portal/<name>.js` on the server (`scriptedPortalKind` in `portal-system.js`, `server/src/field-portal-scripts.js`), as Cosmic `GenericPortal.enterPortal` → `PortalScriptManager` does. There is no separate interpreter: `client/tools/portal-script-compiler.js` rewrites `function enter(pi)` into the NPC compiler's `start()` (`pi` → `cm`, literal `return true/false` → `return`, since `PortalScriptManager` only uses the boolean to re-enable client actions) and compiles it with `compileNpcScript({portal: true})`. Admission, the bounded VM, the worker deadline and dependency validation are the NPC ones.

Portal mode admits only `PortalPlayerInteraction` members whose NPC lowering is the same inherited `AbstractPlayerInteraction` method: `warp`, quest/item/level/job/map reads (`hasItem` is `haveItem`), plus `playPortalSound` (a `portal-sound` effect). Any NPC-only member (dialogs, `dispose`, shops, `getMeso`, `getText`) blocks the source; any other effect (item, quest, saved location) blocks it. Members without local authority become the NPC compiler's lazy traps, failing the request with no effect only when reached: `player-message` (`message`, `playerMessage`, `mapMessage`, `getPlayer().message/dropMessage`), `event-instance` (`getEventInstance`, `getEventManager`, `isEventLeader`, `startDungeonInstance` and any call on their result), `field-state` (`getMap().<anything but getId>`, `getWarpMap`, `resetMapObjects`), `client-presentation`, `npc-conversation` (`openNpc`), `portal-session-state` (`blockPortal`, `getPortal`), `inventory-mutation`, `quest-mutation` and `quest-info-progress` (`containsAreaInfo`). In portal sources a call whose receiver chain contains a trap is itself that trap.

The server runs the program once against the live profile; no warp leaves the character in place. A warp becomes the ordinary transition (`sound` from `playPortalSound`), and the transaction re-runs the program against the fresh draft and rejects the travel unless it reaches the same destination. Supported programs are published as `shops.portalScripts`; their dependencies join the packaged closure and their literal warp maps join the map closure through `admitNpcDestinations`. Type 9 automatic scripts remain unavailable.

Concrete entrances: Ellinia `101000000/26 jobin00` (`enterMagiclibrar`) warps adventurers to `101000003` portal 8 (Grendel); its quest-20718 Cygnus branch traps on `getEventManager`. Henesys Park `100000200/9 in02` (`enterAchter`) warps to `100000201/out02` (Athena Pierce). Both rooms leave through plain portals (`101000003/8 jobout00` → `101000000/jobin00`, `100000201/9 out02` → `100000200/in02`); `outMagiclib` is the Cygnus instance exit. Perion `102000000/27 in02`, Kerning `103000000/27 in03` and Nautilus `120000100/3 ai00` instructor entrances are plain portals. Regression: `server/test/portal-scripts.test.js`.

Of the 458 vendored portal sources, 4 are exact tutorial programs and 31 market translations; of the other 423, 276 compile (173 contain a reachable-in-principle warp, 103 only trap or end) and 147 stay blocked. ### Online transport schedules

Six vendored events share one canonical cycle and compile through the closed reader `client/tools/transport-schedule-compiler.js` (Boats, Trains, Subway, Cabin, Genie, AirPlane; Elevator, KerningTrain, Hak and every instance event stay blocked). It reads, never evaluates: literal times, `getMap(N)` bindings, `em.getTransportationTime`, `scheduleNew` (docked + entry open, schedules stop and takeoff), the stop callback (entry closed), `takeoff` (waiting room → ride `warpEveryone`, random spawn point) and `arrived` (ride → station portal). Supported records are published as `shops.transportSchedules` and their stops extend the map closure.

`server/src/transport-schedule.js` evaluates the cycle as a pure function of wall-clock time anchored at the Unix epoch (OpenMS policy; Cosmic anchors at channel start), so restarts keep one timetable and no timer state is persisted. Moves are level-triggered: a waiting room while undocked is `takeoff` plus that room's `onUserEnter` `warpAhead`; a ride map while docked is `arrived`. Each move is an ordinary server-produced transition (`transport.travel`) retried after refusal. Ticket NPCs admit `cm.getEventManager("<published transport>")` and its `getProperty`; the property snapshot is refreshed when the turn commits, so a departure in between refuses the boarding warp. Any other event manager name keeps the `event-instance` trap.

### Authored NPC travel and World Tour

NPC travel is a separate compiled callback path, not permission to execute raw portal scripts. `npc-script-compiler.js` admits `cm.getPlayer().saveLocation(type)` only for one literal key from the shared [schema8 saved-location inventory](offline-profile.md#schema-8). `npc-script-authority.js` stores the actual current numeric map; `peekSavedLocation` leaves a present slot intact and `getSavedLocation` consumes it. ## Integration and bounded ownership

`await extractPortals(context,map,mapId)` returns `{entities,presentation}`. Main appends entities with final global order and stores `manifest.portalPresentation`. Schema1 records retain `portalId`, `entityId`, graphics status and activation classification. Routes and all original descendants remain solely in `manifest.physics.portals` / `manifest.physics.map.$portalProperties`.

`new PortalTravelGate(clock?)` belongs to `InGameSystems`, never a scene. `tryBegin(packetPath)` returns a unique token or null; `complete(token,outcome)` settles only that exact active token; `cancel(token)` explicitly aborts application-owned work. `PortalSystem(scene,{travel,travelMarket,onError,travelGate})` requires that persistent gate. `handleInput(input)` consumes the latched native Up edge before physics; `update(ms,input)` also handles automatic selection and artwork. `.blocksMovement` exposes pending same-map motion. Scene destruction clears artwork references but **does not cancel or release a travel token**: successful Main commit destroys the old scene before its promise resolves. `finishTravel` always settles the token in `finally`, even after old-owner destruction, without stale UI/error callbacks.

`travel(mapId,targetPortalName,options)` receives `{token,signal,sound,effect,sameMapMotion,notBeforeMs,transition}`. `transition` is `"field"` or `"teleport"` according to the packet path; `notBeforeMs` is admission time, not a120-ms delay. Main validates catalog existence, exact destination-name uniqueness and generation/signal ownership, prepares the candidate, and waits for the opaque boundary on field transitions before committing atomically. Same-map motion relocates the existing scene. Game/Portal iff `options.sound`, and Teleport iff the effect is present, dispatch only after accepted commit. Field reveal does not hold the travel promise until fully visible. Signal cancellation belongs to superseding application work, never automatic source teardown. Hooks are synchronous nonthrowing notification boundaries except the awaited travel promise.

`collectPlayableMaps(context,seeds)` is a bounded synchronous WZ-driven closure export. It shares `portalRouteStatus` with runtime; each ordinary admitted edge must resolve a unique authored destination. Supported NPC routes add their finite map dependencies, while dynamic saved returns refer to admitted source fields. It returns `{ids,blocked}` and fails explicitly at1024 maps. The retained [route closure](ghidra-ingame-portals/route-closure.json) is historical: discovery from its eight seeds reached **356 maps**, including **57 reactor maps /26 reactor templates**, and distinguished the28-map direct neighborhood from full reachability. Its malformed `680000004/4 → 104040002/st02` edge had zero matching destinations and remained blocked. Those totals are not current release counts; explicit selected-map releases are not complete closure claims.

Portal art remains in package-v2 demand-loaded regions using existing atlas identities/budgets. The owner detects changed region entity identities and retains no leases.
