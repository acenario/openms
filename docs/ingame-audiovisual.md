# In-game audiovisual reconstruction

## Provenance and scope

Original client evidence is `/Users/k/Development/tensorfish/Maplestory-Client` WZ archives and `Maplestory_UNPACKED.exe`/retained DLL decompilation. There is no original C/C++ source, Windows execution or original runtime recording. The separately authorized `/Users/k/Development/tensorfish/MapleStory-Server` is Cosmic **server-reference** code only, not client sound/rendering authority or Nexon source. This implementation does **not** establish original visual/audio parity.

Implemented files:

- `client/tools/audiovisual-data.js`: shared-context extraction of exact MP3 payloads, original sound envelopes, map BGM binding and separate effect bundles.
- `client/src/audio/audiovisual-system.js`: committed-scene BGM selection, exact UI/Game sound dispatch, bounded reconstruction controls and one-shot effect inspection.
- `client/src/audio/audio-engine.js`: native decoding, original backend volume curve, bounded PCM ownership and actual output graph.
- `client/src/audio/audio-capture-worklet.js`: pass-through stereo capture after both master gains, before the actual destination.

No fixed-30-ms physics, package-v2 map/region or atlas implementation was changed by this domain.

## Packaged resources

`extractAudiovisual(context,mapIds,weaponSfx)` returns JSON-compatible schema version1. `weaponSfx` comes from the actually selected original equipment metadata:

- `maps[mapId] = {bgm, effect}`. `bgm` is a standard immutable resource descriptor plus `source`, `encoding:85`, original `channels`, original `sampleRate`, `durationMs` and full `envelope` (including original GUIDs, field30, field34, sampleSize, formatFlags and exact formatData hex).
- `sounds.UI[name]` and `sounds.Game[name]` have the same sound descriptor shape. Names are original case-sensitive root node names, not aliases. There are 31 UI and 27 Game nodes in the supplied installation.
- `login.bgm` is the login/title track `Sound.wz:BgmUI.img/Title` in the same descriptor shape. It is reachable from no map's `info/bgm`, so it is published explicitly; native login dispatch for it is not recovered and the descriptor names its exact source. Absent when the original node is absent.
- `effects[name] = {bundle,source,timingSupported:true,activation:"local-preview-only",durationMs}`. `bundle` is the shared immutable visual bundle descriptor. One EntityAnimation entity, `kind:"effect"`, action `play`, is included. No new Frame extension fields are introduced.
- `combat.digits` is a shared visual bundle for the original NoRed/NoBlue/NoViolet/NoCri banks.
- `combat.sounds.Mob[id][name]` and `.Weapon[weaponSfx][name]` are `{available:true,descriptor}` or `{available:false,source,alias,reason}`. Projection includes only current consumers: Damage/Die, Attack1–8, CharDam1/2, and the equipped weapon's Attack. Unresolved original UOLs are preserved as explicit unavailability; no case folding, path repair, substitute sample or swallowed publication error is introduced. An attempted unavailable event reports its source/reason. Absent authored nodes remain absent.

All original MP3 bytes are published unchanged at content-hashed `/generated/audio/<sha256>.mp3` URLs with the shared `resource()` publisher. Same tracks and duplicate UI/Game payloads retain identical hashes. Sound format validation rejects unknown envelopes and non-MP3 encodings explicitly; there is no guessed decode or transcoding fallback.

### Elementary MPEG stream envelope

Read-only measurement of all 163 direct sound nodes in the installation's `Bgm*.img` images found 162 existing WAVEFORMATEX-wrapped MP3 nodes and one native elementary stream, `Sound.wz:BgmGL.img/Amorianchallenge`. Its original envelope is `field30:168081`, `field34:1`, `majorType:83eb36e44f52ce119f530020af0ba770`, `subType:87eb36e44f52ce119f530020af0ba770`, `sampleSize:1`, `formatFlags:1`, `formatType:00000000000000000000000000000000`, with an **empty** format block. These are serialized GUID bytes, not textual GUID byte order.

The [Microsoft MPEG-1 media-type reference](https://learn.microsoft.com/en-us/windows/win32/directshow/mpeg-1-media-types) identifies the native audio combination as `MEDIATYPE_Stream` / `MEDIASUBTYPE_MPEG1Audio` / `GUID_NULL`, with no format structure. Original [Sound_DX8 `51807511`](ghidra-assets/Sound_DX8.dll/decompiled.c#L8079) separately serializes the GUIDs, sample size, flags and conditional format block; its two sentinel comparisons omit the format block entirely. No WAVE fields are synthesized for this stream, and the serializer is unchanged.

The measured payload is 5,378,615 bytes, SHA-256 `3e3a1f3479a72da5f1cdac7ecbe146e694dcea48a3a853d260830be6f70911d9`. Its ID3v2.3 header is `49443303000000000776`: the synchsafe size is 1,014 bytes, so audio begins at offset 1,024. Header `fffbd200` identifies MPEG-1 Layer III, 256 kbps, stereo, 44,100 Hz. Exactly 6,433 complete frames end at offset 5,378,487, followed by a 128-byte `TAG` ID3v1 trailer. Frame sample time is 168,045.714 ms; published duration remains the original `field30` value, 168,081 ms, not a fabricated WAVE duration.

The extractor admits this exact envelope family, independently of track name, and derives channel/rate metadata from validated MPEG headers. It walks consecutive complete MPEG-1 Layer III frames without speculative sync searching, allows variable bitrate/padding but rejects changing channel count/rate, reserved or free-format headers, truncated frames and unrecognized trailing bytes. Optional leading ID3v2.3 framing has checked version, flags, synchsafe size and payload bounds; only a terminal 128-byte ID3v1 tag is excluded from the frame walk. Other ID3 versions and MPEG layers/versions are explicitly unsupported on this new envelope path, not guessed. A 32-MiB encoded-byte cap is a browser extraction safety policy, not an original-game constant. The existing wrapped-MP3 validation remains separate.

A scan of all 3,956 Sound.wz sound nodes found one more envelope family: 40 nodes with WAVEFORMATEX tag `0x0001` (`WAVE_FORMAT_PCM`), mono, 44,100 Hz, 16-bit, `cbSize` 0. They are Mob.img 2110300, 2110301, 3110300, 3110302, 3110303 and 4110300 `Damage`/`Die`, 9420547 `CharDam2`, and Pet.img 5000048, 5000049 and 5000053. Extraction first checks that block alignment, byte rate, sample-length alignment and `field30` duration agree. It then publishes the original 18-byte format block and the untouched samples inside a RIFF/WAVE container (`.wav`, descriptor `encoding: 1`), with no transcoding. Every other format tag remains unsupported. Preflight now validates the audiovisual recipe's full sound set: UI/Game families, combat sounds for the selected maps' mobs, Weapon sounds and login music, through `audiovisualSoundSources`. A future format gap therefore fails in preflight instead of during conversion.

These measurements prove original byte framing, not native decoding, extraction publication or audible playback of the newly covered track. The older 65-node Chromium proof below applies to its original eight-map selection only; it is not evidence for this expanded coverage.

## Runtime integration

Use the assigned API: construct `new AudiovisualSystem(app,services,{onError})`; await `prepare(catalog.audiovisual,signal)`; call `setScene(scene)` only after an atomic committed scene replacement, `update(elapsedMs)` per render and `destroy()` at teardown. `services` are shared `{network,atlases}`. `scene.overlays` must be a persistent world-space container surviving region refresh; preview displays are attached there and removed before their resource owner is destroyed.

Additional public APIs:

- `await playSound("UI"|"Game", originalName)` returns `{status:"playing",source}` or explicit `{status:"gesture-required"}`. Errors/cancellation reject. Callers attach error handling. No event is queued for surprise playback after later enabling audio.
- `await previewEffect(originalName)` is expressly non-authoritative and loads only that bundle. One preview/loading request is owned at a time; new requests/maps abort old loads.
- `await capturePCM(seconds=2)` accepts `0 < seconds <= 5`, one capture at a time. Result includes frames, channels, sampleRate, RMS, peak, nonzero-output `audible` flag, SHA-256 and representation. Zero energy remains visibly **SILENT**, not a successful audible proof. The capture is the real post-master-gain output, not counters, offline synthesis or recorder re-encoding.
  The returned `pcm` is the bounded original interleaved Float32 `ArrayBuffer`, owned by the caller for lossless WAV export. `lastCapture`/`snapshot()` retain metadata only, never the PCM payload.
- `snapshot()` exposes actual context state, active BGM, voices, pending decode count, PCM bytes/cache entries, last native decode, last live capture, active effect/frame and unsupported behavior.

Sound starts unmuted at the documented browser backend preference. Capture-phase, trusted `pointerdown` and `keydown` observers create/resume the AudioContext synchronously on the first browser-supported user activation. They never prevent the action, stop propagation, or move focus; the original click/key continues to gameplay or UI. Concurrent gestures share one graph/BGM startup. Successful startup removes both observers; teardown removes them even if startup is pending. The **Enable / resume audio** control remains available for explicit activation or later suspension. Synthetic events do not unlock autoplay. Worklet support is required and failure remains visible; there is no fake permission prompt or silent success fallback. The worklet is a separate existing dev/build entrypoint beside `atlas-worker.js`.

SysOpt previews both gains/mutes live. Its opening snapshot comes from current audio settings, including unsaved toolbar edits; Cancel restores that snapshot, OK commits, and checkpoint/reload during preview does not save the draft. Resuming a suspended context compares the desired map BGM against the playing source and replaces a stale source rather than treating any existing BGM as current.

UI dispatch follows admitted semantic events, not every DOM activation:

- `UI/BtMouseOver` follows enabled original-control pointer entry; `UI/BtMouseClick` follows an admitted pointer click or Space activation. Parent/keyboard Enter may activate a control but does not inherit a generic click cue. Disabled/cancelled clicks do not play. [Keyboard/button consumers](ghidra-client-corrections/interaction-keyboard-button-sound.txt) and [instructions](ghidra-client-corrections/interaction-keyboard-button-sound-insns.txt) retain the distinction, including `004c0933`.
- `UI/DragStart` follows accepted binding pickup, not an ineligible icon press. `UI/DragEnd` follows accepted binding placement/removal and accepted recovery-item use through the shared `KeyBindings` admission path. Release-only carry, invalid placement, lifecycle cancellation and rejected use do not fabricate a completion cue. See [carry consumers](ghidra-client-corrections/fidelity-r3-carry-state.txt).
- Opening a notice, reporting unsupported behavior, saving a local profile or changing a draft does not imply `UI/DlgNotice`. There is no generic notice fallback or invented sound for an unsupported action.
- Local error diagnostics deliberately map the original request-notice `UI/Invite` sample to the browser-only Game Logs notification. Its native request consumer is `005230f3`/string`0x4d3` through `00989588`; this is not `UI/DlgNotice` or a fabricated server response. Failed audio notification records its error without recursively requesting another notification.
- Incoming social consent dispatches original `UI/Invite` through `GameUI.sound` → the existing audiovisual engine on first successful prompt layout. [Original FadeYesNo instructions](ghidra-client-features/dialogs/notification-instructions-50-58.txt) resolve string`0x4d3` and call `00989588` at `00522cf4`, `00522ee6`, `005233da` (trade uses `0052310b`). ### Observed server skill presentation

The server publishes authored skill sequences as `skill.visual` rows whose `depth` is the effect's **intra-sequence** z (`server/src/skill-resources.js` `animationView`), not an absolute world z. The browser used to apply it literally, so every observed effect landed at world 0 behind the map and actors. `client/src/online/native-skill-presentation.js` now composes it onto the native effect layer **398500** — the same layer the gameplay-effect, combat-presentation and audiovisual owners already use — via `skillEffectDepth`. A mount/morph visual (`replacesActor`) instead borrows its caster's current entity depth so it replaces that actor rather than covering the field.

Local casts start their original `Use` artwork and sound without waiting for the result. The shared resource cache and atlas/audio limits still own preparation, so uncached artwork can require a download. Ordinary Use effects follow the local actor; Flash Jump and Soul Rush fallback artwork retain their fixed cast origin. This feedback changes presentation only: HP/MP, buffs, damage, loot and success effects still follow confirmed gameplay.

The server attaches the cast operation's `feedbackId` to matching visual/sound publications. The local owner suppresses an already-played matching cue, including later state snapshots; if the server cue wins a slow asset load, local preparation yields to it. Refusal, field exit and destruction release staged visuals/leases and stop remaining audio. A short sound already heard cannot be undone. Up to 32 cast records are retained for 60 seconds, with completed confirmed records reclaimed when needed for continued play. `prepareSound` also no longer drops a cue when the AudioContext is still resuming: a cast is a trusted gesture, so it awaits `enableAudio()` once and keeps the voice instead of silently discarding it. Ordinary ranged impact cues and the per-projectile/per-mob impact selection remain qualified below.

Projectile visuals are sampled at the 11 Hz publication cadence, so the client now chases each published sample across one publication interval (matching peer positions and drop rotation) instead of snapping, which removed the visible 90 ms teleport stagger on thrown skills such as Three Snails.

Local and observed skill artwork are verified by `server/tools/check-skill-effects.js` (isolated database at 500 ms RTT, pending chat, native cast with replies held for three seconds, early visual/audio and echo reconciliation) and visual evidence in a Chromium session; the layering math is pinned by `client/test/skill-projectile-chase.test.js`.
